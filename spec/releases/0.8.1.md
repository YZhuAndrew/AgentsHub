## Summary

AgentsHub 0.8.1 is a hotfix release repairing two v0.8.0 regressions reported
by users on the day of publication:

1. **Startup / Skills-page performance regression.** Every desktop
   `initDatabase()` call ran `reconcileCanonicalWorkspaces()`, which
   unconditionally re-materialized every canonical Skill workspace (456 MB of
   delete + copy on a 228-skill library) and was triggered multiplicatively
   through an uncached custom-agent settings read on the batch install-status
   path. Users saw multi-second startup stalls and an unresponsive Skills
   page. Fixed by bundle-hash change detection in
   `hydrateCanonicalSkillWorkspace`, a per-process reconcile memo in both
   `initDatabase` wrappers, and a TTL-cached
   `readCustomAgentsFromSettings()`. Measured on the reporting machine:
   launch → interactive 80 s+ (never completed) → 3.3 s; startup
   canonical → proxy gap 5.5 s → 1.8 s.
   See `spec/changes/active/canonical-workspace-reconcile-performance/`.

2. **Startup lockout for symlink-carrying imported skills.** Intra-package
   relative symlinks (the `AGENTS.md -> CLAUDE.md` alias pattern) made the
   v0.8.0 startup canonical authority publication refuse forever, and backups
   containing recreated links could not be restored. Fixed by the
   `symlinkPolicy: "record"` rollout with per-context copy policies:
   contained links materialize in canonical projections and recreate with
   relativized targets in snapshots; escaping links still fail closed.
   See `spec/changes/active/storage-inventory-symlink-containment/`.

## Contents

### Fixes

- **Canonical workspace hydration change detection**
  (`fix(core)` `canonical-workspace-reconcile-performance`): workspaces whose
  `.canonical-bundle-hash` matches the bundle manifest `contentHash` are
  reused as-is; reconcile runs at most once per process per data root;
  custom-agent settings reads are cached for 5 s and invalidated on settings
  updates.
- **Storage-inventory symlink containment**
  (`fix(core)` `storage-inventory-symlink-containment`): ENOENT-only dangling
  classification, `preserve` / `preserve-strict` copy policies, projector
  materialization of contained package links, restore-side fail-closed
  containment validation, and journal/snapshot parity across backup, restore,
  portable restore, and storage-root migration.
