# AgentsHub 0.8.3 Release Record

## Release

- Version: `0.8.3`
- Tag: `v0.8.3`
- Date: 2026-08-16
- Channel: Stable (fork)
- Status: Published (workflow_dispatch build; draft promoted to latest after asset and update-manifest verification)

## Summary

AgentsHub 0.8.3 is an emergency hotfix release repairing two blank-window
defects reported during local testing of the packaged build, and shipping the
runtime performance work that landed after v0.8.2.

1. **Startup fails after browsing the workspace directory in Finder.**
   macOS drops a `.DS_Store` into any directory the user opens; the canonical
   graph inventory walk treated any undeclared file as fatal, so every launch
   aborted during bootstrap and the window opened blank (dev mode uses a
   different user-data directory and was unaffected). The walk now ignores OS
   metadata files (`.DS_Store`/`Thumbs.db`, any depth) — the same convention
   `storage-inventory` already applied — while any other undeclared file is
   still strictly rejected. This defect existed in the published v0.8.2 as
   well. See
   `spec/changes/active/canonical-inventory-os-metadata-tolerance/`.

2. **Packaged build opens to a blank window (renderer init failure).** The
   function-form `manualChunks` introduced with the post-0.8.2 chunking
   optimization let Rollup place the shared commonjs interop helper in
   `i18n-vendor` while `react-vendor` also referenced it, creating a circular
   chunk initialization; `react-i18next`'s top-level `React.createContext`
   ran against an uninitialized React binding and killed the renderer. The
   helper now has a deterministic home in `react-vendor`. Regression
   introduced and fixed within the post-0.8.2 line; never published. See the
   appended record in
   `spec/changes/active/runtime-perf-optimizations/implementation.md`.

Also ships the performance work from `runtime-perf-optimizations`,
`workspace-sync-incremental`, and `startup-db-integrity-consolidation`:
targeted workspace sync (per-mutation writes proportional to affected
prompts instead of the whole library), FTS trigger narrowing, single-
transaction prompt creation, markdown hot-path memoization, AI-test stream
throttling, jsx-runtime chunking (with the cycle fix above), parallel
startup fetches, web static caching/compression, stat-based media
existence, and the web N+1/double-fetch elimination.

## Contents

### Fixes

- **Canonical inventory tolerates OS metadata** (`fix(core)`
  `canonical-inventory-os-metadata-tolerance`): `.DS_Store`/`Thumbs.db`
  ignored at any inventory depth; ordinary undeclared files still fail
  verification.
- **Circular chunk initialization broken** (`fix(desktop)`
  `runtime-perf-optimizations` follow-up): `commonjsHelpers` pinned to
  `react-vendor`; packaged renderer verified at runtime via CDP (full main
  UI rendered, 0 exceptions).

### Performance

- Targeted prompt workspace sync + relation/format zero-write; affected-id
  returns from `renameTag`/`deleteTag`/`movePrompt`; `getVersionById`.
- FTS update trigger narrowed to indexed columns (idempotent migration
  `narrow_prompts_fts_update_trigger_v1`); `create` single transaction.
- Startup integrity scans 4 → 2 per healthy open; canonical-authority
  upgrade path reuses the source database handle.
- Markdown memoization (`MarkdownMemo`), AI-test stream flush throttling
  (100 ms), markdown stack off the startup critical path, parallel
  prompts/folders fetch.
- Web: immutable asset caching + ETag 304 + gzip; `/exists` via `stat`;
  sync N+1 and double version fetch eliminated.
