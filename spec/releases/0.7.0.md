# AgentsHub 0.7.0 Release Record

## Release

- Version: `0.7.0`
- Tag: `v0.7.0`
- Date: 2026-08-13
- Channel: Stable (fork)
- Status: Published

## Summary

AgentsHub 0.7.0 ships Skill batch import (local ZIP + multiple Git URLs) on top
of `0.6.2`, adds the QwenWork CN agent platform, unifies Skills platform
visibility with the Settings toggle, and corrects the `trae-work-cn` root
directory.

## Contents

### Features

- **Skill batch import** (`feat(skill)`): a new "Batch Import" mode installs one
  or more local `.zip` archives (drag/drop or file picker) and/or multiple
  GitHub/Git URLs in a single action, with preview, per-item failure isolation,
  progress, a failure list, and a summary. Dropping one or more ZIPs onto the
  My Skills view opens batch import pre-filled. Local ZIP install is routed
  through a new `local-zip` source kind in the existing atomic package lifecycle
  (reusing the hardened extractor, fingerprint, safety review, and atomic
  replace) rather than a parallel install path. See
  `spec/changes/active/skill-batch-import-zip-and-multi-url/`.
- **QwenWork CN platform** (`feat(skill)`): registers the `qwenworkcn` built-in
  agent platform target (China-region variant of QwenWork) with its
  capabilities, icon, order, and reference doc.

### Fixes

- **Unified platform visibility with the Settings toggle** (`fix(skill)`):
  Skills distribution/Agent list membership now follows the Settings "enabled"
  toggle as the single source of truth (enabled = visible everywhere, disabled =
  hidden everywhere); on-disk detection is demoted to a non-blocking hint;
  `copilot`/`amp` were added to `DEFAULT_SKILL_PLATFORM_ORDER` so Settings and
  Skills sort identically. See
  `spec/changes/active/unify-skill-platform-visibility/`.
- **trae-work-cn root** (`fix(skill)`): the `trae-work-cn` default root changes
  from `~/.trae-work-cn` to `~/.trae-cn` (shares the TRAE IDE CN data directory,
  user-confirmed). See `spec/changes/active/fix-trae-work-cn-root-dir/`.

### Version Bumps

- Root, Desktop, CLI, self-hosted Web, Cloudflare Worker, and Mobile manifests
  report `0.7.0`, including Expo app metadata. `CLI_VERSION` constant and the
  CLI `--version` test updated to match. Private shared packages retain their
  independent `0.1.0` versions.

## Distribution

- Desktop: macOS arm64 + Windows x64 + Linux builds produced by the `release.yml`
  workflow on the `v0.7.0` tag push (**unsigned**; signing/R2 secrets not
  configured in this fork, so Cloudflare R2 mirror sync is skipped). Release
  artifacts are named `AgentsHub-${version}-*` per the electron-builder
  `productName`.
- Release is created as a **DRAFT** by the workflow and promoted to latest via
  `gh release edit v0.7.0 --draft=false --latest` after the build succeeds.
  Once promoted, the desktop auto-updater picks up the new version.

## Known Caveats

- macOS builds are not Apple Developer-ID signed or notarized. On first launch
  macOS Gatekeeper may block the app; users can run
  `sudo xattr -rd com.apple.quarantine /Applications/AgentsHub.app`.
- Cloudflare R2 mirror is not populated for this release (R2 secrets not
  configured); downloads resolve through the GitHub release assets.
- Default `disabledPlatformIds = []` means the Skills distribution list now shows
  every enabled platform by default (longer than the old detected-only list);
  this is the intended consistency with the Settings toggle, mitigated by
  ordering, the not-detected hint, and user-managed toggles/order.

## Rollback

Before publication, revert the version bumps and the four feature/fix commits
(QwenWork CN, visibility, batch import, trae-work-cn root). This release changes
no database schema. Note that `trae-work-cn` previously installed to
`~/.trae-work-cn`; after this release it resolves to `~/.trae-cn`, so any
pre-existing installs under `~/.trae-work-cn` are not auto-migrated.
